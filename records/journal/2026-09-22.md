# Daily Journal: 2026-09-22

## Wins

### Autonomous Container Image Update Alerting
Completed integration of Diun (Docker Image Update Notifier) within Homelab Core:
- Isolated container inspection through `socket-proxy`, maintaining strict read-only access without exposing the raw `/var/run/docker.sock`.
- Integrated automated email alerts to `admin@roadtotech.me` routed directly via Stalwart mail server.

---

## Incidents & Debugging

- [Incident RCA & System Integration: Diun Docker Provider Connectivity & Stalwart Mail Notification](../debug/2026-09-22-diun-socket-proxy-integration-and-stalwart-alerting.md)
  - **Issue**: Diun failed with `Cannot connect to the Docker daemon at tcp://socket-proxy:2375` at startup and reported `WRN No image found` with `WRN No notifier available`.
  - **Root Cause**: `diun` was not attached to the `socket-net` network bridge preventing DNS resolution to `socket-proxy:2375`, default watch policies excluded stopped or untagged containers, and SMTP alert notifications were undeclared.
  - **Remediation**: Joined Diun to `socket-net` and `proxy-net`, declared container watch policies, and configured internal SMTP notifications against Stalwart on port 25.

---

## Mistakes and Lessons Learned

### Network Bridge Attachments for Daemon Proxies
When using intermediate security proxies like `socket-proxy` to isolate the Docker daemon, consumer services must explicitly attach to the dedicated socket network bridge (`socket-net`), otherwise name resolution fails closed before API negotiation starts.

### Non-Authenticated Internal SMTP Deliverability
Direct delivery from internal platform services to local mailboxes on the same domain (`kiskaadee@roadtotech.me`) does not require SASL authentication when routing within internal Docker bridges, provided the mail server treats the local subnet as trusted for local-recipient delivery.
